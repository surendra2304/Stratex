## What I Did Today

Today was cloud deployment day. I packaged the entire algorithmic trading bot inside a Docker container and successfully deployed it to Render cloud infrastructure for continuous 24/7 autonomous operation. Getting this running smoothly in production required resolving multiple infrastructure and architectural challenges.

I engineered the production containerization setup:
- Created `Dockerfile` configuring Python 3.11 with all necessary scientific and financial computing libraries.
- Built `docker-compose.yml` for local container testing.
- Created `render.yaml` to manage declarative Infrastructure-as-Code deployments.
- Implemented `scripts/supervise_services.py` to act as the primary container supervisor entrypoint. It runs both the trading engine (`bot.py`) and the web dashboard (`dashboard.py`), actively monitoring their health and automatically restarting either process if an unexpected fault occurs.

The first major hurdle occurred immediately upon cloud launch: Binance REST and WebSocket endpoints returned HTTP 451 "Unavailable For Legal Reasons" and HTTP 403 Forbidden errors. The root cause was that Render defaulted to United States datacenter regions (Oregon/Ohio), which Binance strictly geo-blocks. I resolved this by pinning the deployment explicitly to the Frankfurt, Germany datacenter (`region: frankfurt`) inside `render.yaml`. The bot connected cleanly on the very next boot.

I also thoroughly standardized the accounting equations across the platform to ensure mathematical correctness:
$$\text{Total Equity} = \text{USDT Cash} + \text{Active Managed Crypto Value}$$
Prior to this fix, realized profits were inadvertently added to cash while also being added as a distinct component of equity, creating an artificial inflation bug. I eliminated this double-count permanently.

Furthermore, I added fill deduplication logic to prevent partial exchange fills from creating duplicate trade ledger records, and introduced `/health` and `/ready` endpoints for automated Render health checks.

By the end of the day, the container was fully operational in Frankfurt, connected to Binance Testnet with real-time WebSocket streams across 13 crypto pairs. The test suite expanded to 312 passing tests with a 100% pass rate.

## Bugs I Fixed

**Bug #10 — Python List Hashability TypeError in Service Loop**
The main service loop crashed with `TypeError: unhashable type: 'list'` because timeframe lists like `['5m', '15m']` were being used as dictionary keys. Because Python lists are mutable, they cannot be hashed. I converted all timeframe identifiers to immutable string keys. Commit `8e0c165`. Resolved ✅

**Bug #11 — Render US Region Geo-Blocking (HTTP 451 / 403)**
After deploying to Render, the container failed to authenticate with Binance because US datacenter IP addresses are geo-blocked. I updated `render.yaml` to hard-pin the deployment to `region: frankfurt`. Commits `92e779e` and `da7937b`. Resolved ✅

**Bug #12 — Docker Entrypoint Windows CRLF Line Ending Crash**
The container initially failed on startup with `/bin/sh^M: bad interpreter: No such file or directory`. The entrypoint shell script written on Windows retained CRLF line endings. I normalized all bash entrypoints to Unix LF line endings. Commit `e81ffa9`. Resolved ✅

**Bug #13 — Realized PnL Double-Counting in Portfolio State**
Total account equity was inflating after trade closures because realized profit was credited to cash and simultaneously summed into total equity. I enforced the strict single-source formula `Total Equity = Cash + Crypto Holdings` and eliminated the duplicate credit. Commit `6aeb104`. Resolved ✅

**Bug #14 — Duplicate Exit Order ID Ledger Pollution**
When an order filled across multiple partial fills, the ledger recorded duplicate close events for each partial fill. I implemented an exit order ID deduplication map inside `_get_trades_data()` to guarantee exactly one closed trade record per order lifecycle. Commit `6aeb104`. Resolved ✅

**Bug #15 — Reconciliation Lock Thread Blocking**
The strategy scanner stalled during periodic portfolio reconciliation audits because balance queries held a global thread lock synchronously. I replaced it with a non-blocking cached balance audit mechanism. Commit `08658ba`. Resolved ✅
