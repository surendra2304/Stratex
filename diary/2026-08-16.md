## What I Did Today

Today was deployment day. I packaged the entire bot inside a Docker container and got it running 24/7 on Render cloud hosting. It was more frustrating than I expected — there were several blockers before the bot was finally live and healthy.

First I wrote the `Dockerfile`, `docker-compose.yml`, and `render.yaml` files to package both the trading engine (`bot.py`) and the web dashboard (`dashboard.py`) together. I also built a production supervisor script (`scripts/supervise_services.py`) that runs as the container's entrypoint — it monitors both processes and automatically restarts either one if it crashes or becomes unresponsive.

The first big problem hit immediately after deploying to Render: the bot was getting HTTP 451 "Unavailable For Legal Reasons" from Binance. Render's default datacenter is in the United States, and Binance blocks US-region IP addresses. I had to create a new `render.yaml` blueprint that pins the deployment explicitly to the Frankfurt, Germany region (`region: frankfurt`). That fixed it.

While getting deployment running I also standardised the portfolio accounting formula to make sure `Total Equity = Cash + Crypto Holdings Value`. There had been a subtle bug where realized profits were being added to the cash balance but also being counted in total equity separately, inflating the equity figure artificially. I also added order fill deduplication so partial fills do not generate duplicate ledger entries.

By end of day I had the container live on Render (Frankfurt), authenticated to Binance Testnet, and streaming market data across all 13 pairs. The balance showed $11,290.39 USDT. I had 312 automated tests passing (100% pass rate).

## Bugs I Fixed

**Bug #10 — Python List Hashability TypeError in Service Loop**
The service loop crashed with `TypeError: unhashable type: 'list'` because I had timeframe lists like `['5m', '15m']` being used directly as dictionary keys. Python lists cannot be used as dict keys because they are mutable. I converted all timeframe identifiers to immutable strings or tuples before using them as keys. Commit `8e0c165`. Resolved ✅

**Bug #11 — Render US Region Geo-Blocking (HTTP 451 / 403)**
After deploying to Render, the container kept crashing with HTTP 451 from Binance because Render's default regions (Oregon and Ohio in the US) are geo-blocked by Binance. I created a `render.yaml` Blueprint that hard-pins the service to `region: frankfurt`. Commits `92e779e` and `da7937b`. Resolved ✅

**Bug #12 — Docker Entrypoint Windows CRLF Line Ending Crash**
When the container first started it immediately failed with `/bin/sh^M: bad interpreter: No such file or directory`. The shell scripts I wrote on Windows had CRLF line endings. Linux needs LF. I converted all shell scripts to Unix LF line endings. Commit `e81ffa9`. Resolved ✅

**Bug #13 — Realized PnL Double-Counting in Portfolio State**
Total account equity was inflating whenever a trade closed because realized profit was being added to the cash balance AND being summed into total equity separately. I enforced the strict formula `Total Equity = Cash + Crypto Holdings` and removed the double-count. Commit `6aeb104`. Resolved ✅

**Bug #14 — Duplicate Exit Order ID Ledger Pollution**
When a trade filled in multiple partial fills, the ledger recorded duplicate close events — each partial fill was treated as a separate trade closure. I implemented an exit order ID deduplication map inside `_get_trades_data()` to prevent this. Commit `6aeb104`. Resolved ✅

**Bug #15 — Reconciliation Lock Thread Blocking**
The strategy evaluation loop was stalling during the periodic portfolio reconciliation audits because the balance query was holding a global lock synchronously. I replaced it with a non-blocking cached balance audit that runs independently. Commit `08658ba`. Resolved ✅
