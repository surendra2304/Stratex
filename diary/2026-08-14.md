## What I Did Today

Today was Day 1 of the project. I built everything from scratch — the data pipelines, quantitative indicators, first trading strategies, risk management rules, and the initial dashboard. It was a very long day but I got a solid foundation in place.

I started by connecting to the Binance REST API to download historical candle data and stream real-time prices. From there I built the core technical indicator library inside `features.py` — that includes EMA(9), EMA(21), EMA(50), EMA(200), RSI(14), ATR(14), ADX(14), Bollinger Bands, MACD, and Volume Delta. These are the mathematical building blocks every strategy runs on.

I also split the data and account access into two completely separate clients. `data_client.py` handles all public market data with no credentials, while `account_client.py` handles authenticated private account queries. This was an important design decision — I never want to accidentally expose API keys in a public data call.

On the strategy side, I implemented four initial strategies: a Scalper (`strategy_scalper.py`), a Swing (`strategy_swing.py`), a Machine Learning model (`strategy_ml.py`) powered by XGBoost (`model_buy.pkl`, `model_sell.pkl`), and an Aggressor (`strategy_aggressor.py`). The backtest simulation engine (`backtest_engine.py`) runs walk-forward optimization against these strategies.

One thing I made absolutely non-negotiable from day one: every trade that gets placed automatically gets OCO (One-Cancels-the-Other) bracket protection with a Stop Loss and a Take Profit. No trade is ever left naked in the market.

I built `CostEngine` to enforce a mandatory 0.31% round-trip friction hurdle — that is 0.10% maker fee + 0.10% taker fee + 0.11% slippage buffer. Any signal that cannot overcome that friction bar gets silently rejected before an order is even considered.

The initial web dashboard (`dashboard.py`, `static/index.html`) went up showing real-time portfolio value, open positions, and a live chart feed.

By end of day I had 275 automated tests written and passing (100% pass rate).

## Bugs I Fixed

**Bug #01 — Windows Console UTF-8 UnicodeEncodeError**
When I started the dashboard on my Windows machine in PowerShell, it immediately crashed with `UnicodeEncodeError: 'charmap' codec can't encode characters`. The problem was that PowerShell uses `cp1252` encoding by default, which chokes on UTF-8 currency symbols and emoji. I fixed it by wrapping the standard output stream with `io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')`. Commit `82883cc`. Resolved ✅

**Bug #02 — Binance Spot OCO Parameter Rejection (HTTP 400)**
When I tried to place my first bracket order on Binance Testnet, it came back with HTTP 400 Bad Request. I had used the wrong order type — `STOP_LOSS` instead of `STOP_LOSS_LIMIT`. The Spot API requires a proper limit price alongside the stop trigger. I fixed the payload to use `STOP_LOSS_LIMIT` with both `stopPrice` and `price` fields. Commit `64452f0`. Resolved ✅

**Bug #03 — ML Feature Calculation Lookahead Bias**
The XGBoost model was showing suspiciously high 85%+ win rates in backtesting. When I dug in I found the problem — features were being normalised across the entire dataset before the train/test split, which means the model was seeing "future" data during training. I fixed this by shifting all feature arrays back by 1 period (t-1) and restricting scaling strictly to the historical window before each prediction point. Commit `237045e`. Resolved ✅

**Bug #04 — Execution Friction Underestimation**
Trades that looked profitable on paper were coming out as net losses. The signal generator had been assuming zero fees and zero slippage. I fixed this by building `CostEngine` which requires `expected_gross > 0.31%` before any signal is dispatched to the execution layer. Commit `4090682`. Resolved ✅

**Bug #05 — API Credential Leakage in Public Client**
I noticed the authenticated Binance client was being reused for public market data queries. This is a security risk — any bug that leaks the public client's response could reveal key material. I separated them into `MarketDataClient` (no credentials) and `ExecutionClient` (private, key-authenticated). Commit `1023495`. Resolved ✅

## Important Decisions

I decided to enforce OCO bracket orders as a hard requirement on every trade. The bot will never place an unprotected position — it is too easy for a connection drop or process crash to leave a position running without a stop loss.
