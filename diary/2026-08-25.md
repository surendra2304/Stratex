# August 25, 2026

## What I Did Today

Today I fixed several critical trading engine problems that were blocking the aggressive scalper from running properly, resolved dashboard number sync issues, and cleaned up multiple execution errors I found in the logs.

**Scanner Crash Protection & API Rate-Limit Backoff:**
The market scanner and order execution loops had been crashing whenever Binance sent back an unexpected error response — a single bad API response was taking down the whole evaluation loop. I wrapped all critical sections with proper exception handlers so network hiccups, timeout errors, and exchange API errors are caught and logged without crashing the engine. I also implemented an automatic 60-second backoff pause whenever Binance sends an HTTP 429 rate-limit warning, so the bot never risks getting IP-banned from the exchange.

**Removing Position & Exposure Limits:**
The aggressive scalper was being blocked from opening new positions by the risk gate's `MAX_OPEN_POSITIONS` limit. I raised this to 999 (effectively unlimited) and raised `MAX_EXPOSURE_PCT` to 999.0. The scalper needs to be able to open positions freely whenever clear signals appear — having a hard cap of 5 or 10 positions was completely defeating the purpose of running it across 16 coins and 6 timeframes simultaneously.

**Fixed Scalper Stop Loss & Take Profit:**
I replaced the ATR-based exit calculations with fixed percentage targets. The ATR values on 1-minute charts are tiny and the bot was getting stopped out instantly by normal market noise. The new targets:
- **Stop Loss**: Entry Price × 0.995 (0.5% away from entry for Longs)
- **Take Profit**: Entry Price × 1.003 (0.3% away from entry for Longs)
- Inverted for Shorts (SL = Entry × 1.005, TP = Entry × 0.997)

I also added a pre-trade margin check before every order submission. If the available margin is insufficient for the position size, the trade is cleanly skipped with a log message rather than sending the order to Binance and getting a rejection error code back.

**Fixed Risk Gate Blocking Signals:**
I discovered that valid candidate signals were being silently blocked by the drawdown risk gate because it was comparing against a stale historical drawdown value from old test sessions rather than today's actual equity. I fixed the drawdown calculation to measure from today's opening equity peak only — which brought the displayed drawdown to a healthy 0.00% and unblocked all the signals that had been incorrectly filtered.

**Fixed Boot Reconciliation — Futures Permission Errors:**
The startup reconciliation check was trying to use spot market order endpoints on a Futures account, which was causing `-2015 Invalid API-key / permissions for action` errors in the logs. I updated the boot reconciliation to use Futures-specific endpoints. The permission errors stopped immediately.

**Dashboard PnL Sync & Profit Factor Formatting:**
I aligned the "Today's PnL" calculation on the dashboard to correctly sum today's closed trade profits plus the current unrealized PnL from open positions. Previously there was a mismatch between what the engine tracked internally and what the dashboard displayed. I also formatted the Profit Factor to always display exactly 2 decimal places (e.g. "1.48" instead of "1.4800000000001").

I ran the full automated test suite twice — all **548 tests passed (100%)** on both runs. Everything was deployed live to Render and verified working.
