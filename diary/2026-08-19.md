## Bugs I Fixed

**Bug #35 — HTML Structural Corruption from Sequential Replacement Scripts**
Running the `rewrite_*.py` scripts sequentially was causing each script to overwrite DOM markers that the previous one had just inserted, creating a structurally corrupted `index.html`. I solved this by building `build_full_ui.py` which compiles all views from constant template strings in one pass. Resolved ✅

**Bug #36 — Missing /api/config Endpoint and apiClient.post Method**
The Settings page was calling `/api/config` for GET and POST operations but the endpoint did not exist in `dashboard.py`, and `apiClient` in `static/app.js` only had a `.get()` method. I implemented the safe `/api/config` endpoint and added the `post()` method with JSON body serialization. Resolved ✅

**Bug #37 — Polling Contention and View Switching Routing Mismatch**
The navigation tab click handlers were referencing legacy view IDs (`signals`, `market`, `activity`) that no longer existed in the redesigned terminal. And `fastPoll()` was querying all views simultaneously on every tick. I updated tab click routing to the correct 10 view IDs and added intelligent active-view routing in `fastPoll()`. Resolved ✅

**Bug #38 — Frontend JS Syntax Error on Duplicate Variable Declaration**
The JavaScript file had a duplicate `let activeMarketSymbol` declaration which completely halted script evaluation on load. I removed the duplicate, added URL hash routing for bookmarkable view navigation, permanently blocked the live execution path in `execution.py`, restricted CORS to Frankfurt Render and local dev origins, and added input validation to `/api/config`. Resolved ✅

## Important Decisions

I adopted `build_full_ui.py` as the permanent approach for frontend assembly. Trying to manage 10 views with sequential patch scripts is too fragile — a compiler approach gives me reliable, reproducible output every time.
